# Classes

Each extends Topside's class (`TKColumn`, `TKRow`, `TKFixed`, `TKFlow`, `TKLabel`, `TKButton`, `TKCheckbox`, `TKToggle`, `TKDropdown`, `TKTextInput`, `TKComboBox`, `TKDatepicker`, `TKLink`, `TKSeparator`, `TKProgressBar`, `TKSpinner`, `TKSlider`, `TKToggleButton`, `TKSegmentedControl`, `TKImage`, `TKScrollView`, `TKTabView`, `TKSplitView`, `TKGrid`, `TKOverlay`, `TKTable`, `TKTextArea`, `TKListView`, `TKCollectionView`, `TKTree`, `TKWebView`) and fills in its hooks; the driver's `$primitives` map names them. Fonts and alignment of what shows text are in `QtText`. Shared native work is in `QtNative`, what column and row share in `QtBoxChildren`.[^native]

| Class | Native |
|---|---|
| `QtColumn`, `QtRow` | `QWidget` with a `QVBoxLayout` / `QHBoxLayout`, a trailing stretch that gives way when a child fills; a child's stretch and alignment set in the layout (`childLayoutChanged()`); padding as the layout's margins, each side its own, live. In a column, a child aligned across (start, center, end) or filling up to a maximum width sits in a row of its own (a `QHBoxLayout`: child + stretch, stretch + child, stretch + child + stretch, or child at stretch 1 + stretch at 0), because a `QVBoxLayout` asks every child for its height at the column's whole width (`QBoxLayoutPrivate::calcHfw`) and only then places an aligned or capped child narrower (`QWidgetItem::setGeometry`): wrapped text got too little height and what follows overlapped it. A row asks each item at the width it gets. Needs ext-qt 3ac68d5 / eb6c7d3 (`insertLayout`, `removeItem`) |
| `QtFixed` | `QWidget` without a layout: child widgets at their frames (`setGeometry`); its minimum size covers every frame |
| `QtFlow` | `QWidget` with no layout: Qt has no wrapping layout for widgets (its documented answer is the Flow Layout example, a `QLayout` that sets each child's geometry from its size hint), so the children are placed the same way in PHP. Each shown child at its `sizeHint()` (an invalid hint is 0), kept within its minimum and maximum size and within the width of a line, moved in by its left and top margin (`QtHeldMargin`); the next goes right of it plus `spacing`, or onto the next line (`y` plus the line's height plus `spacing`) where it no longer fits; lines start at the left padding. A hidden child takes no room. Placed again on every `RESIZE` and `LAYOUT_REQUEST` of the widget (a `QEventFilter`; a child whose hint changed asks its parent for a layout), and on attach, detach, reorder, spacing, padding, a child's margin and its visibility. The widget's minimum height is the larger of `minSize()`'s and the height the lines need, so a column holding it grows as it wraps; its minimum width is the larger of `minSize()`'s and the widest shown child's box (size plus margin) plus the left and right padding, set on every placing, so no child is cut and a flow without fill (a plain `QWidget` has no size hint) is never zero wide; a hidden widest child no longer counts. `tests/Integration/FlowTest.php` reads the real geometry |
| `QtLabel` | `QLabel` with plain text, left-aligned at build; font (in pt) and colour in its style sheet. Truncating: a `QLabel` never elides, so the label shows its text cut to its width (its `width()` less its sheet margin) with `QFontMetricsF::elidedText(…, ELIDE_RIGHT, …)` (needs ext-qt aae5370), again on each `RESIZE`, `FONT_CHANGE` and `STYLE_CHANGE` (a `QEventFilter` installed at build; a style sheet's font comes as a font change) and each new text; runs are cut run by run, each measured in a `QFont` of the label's family and size in the run's weight (bold 700) and slant (the run's, or the label's `FontSpec`), the run that does not fit cut and the rest dropped, shown as rich text. Before the label has a width it shows the text whole. Minimum width at least 1 (a minimum of 0 makes Qt use the whole text's hint) and, while it does not fill, width policy `IGNORED`; word wrap off while truncating. Measured 2026-11-26 offscreen: in a 200-point window the label is within 200 and ends "…"; at 400 more shows; at 1200 the whole text; whole, its hint is over 200 |
| `QtButton` | `QPushButton` with Qt's own focus policy; `&` doubled; `clicked()` calls `clicked()`; a border is set with a background so the bezel does not cover it; styles, icon and role under Settings |
| `QtCheckbox` | `QCheckBox`; `toggled(bool)` reports the new state (Qt emits it for `setChecked()` too, which topside ignores as the state it holds) |
| `QtToggle` | Qt has no switch: a horizontal `QSlider` with two positions (0 off, 1 on), fixed 40×22, styled as a pill with a round knob through `subControlSheet()`; `valueChanged(int)` reports the state |
| `QtDropdown` | a holder `QWidget` (zero-margin `QHBoxLayout`) with a `QComboBox` and, shown instead while icon-only, an auto-raised icon-only `QToolButton` whose `QMenu` opens at once (`INSTANT_POPUP`): Qt's own icon button with a list. A `QComboBox` has no icon-only face: sized to its icon (`ADJUST_TO_MINIMUM_CONTENTS_LENGTH_WITH_ICON`) it cuts the icon (measured: 768 of 1024 pixels under the macOS style, none under Fusion). `currentIndexChanged(int)` reports the choice, ignored while its items are replaced (`clear()` and `addItems()` emit it); a menu action's `triggered(bool)` sets the combo box, which reports it. An option's icon is its item's and its action's (`QtIcon`: the file, else the theme's); the button shows the selected one's. `ADJUST_TO_CONTENTS`: Qt's default sizes a combo box on first show only, so later options and icons were cut. Focus goes to the face shown |
| `QtTextInput` | `QLineEdit`; a search field has Qt's clear button and the theme's search glyph |
| `QtComboBox` | editable `QComboBox` with an unfiltered `QCompleter`; one Return (two `returnPressed`, maybe an `activated`) is one submit. Qt closes the popup when the app stops being active |
| `QtDatepicker` | `QDateEdit` with calendar popup; its `clicked(QDate)` reports picking the day shown |
| `QtLink` | rich text `QLabel` with one escaped anchor and `openExternalLinks` |
| `QtSeparator` | `QFrame` line |
| `QtProgressBar` | `QProgressBar`; a range of nothing is indeterminate |
| `QtSpinner` | Qt has none: a short indeterminate `QProgressBar` over a spacer, hidden while stopped |
| `QtSlider` | `QSlider` over 10000 steps |
| `QtToggleButton` | checkable `QPushButton` |
| `QtSegmentedControl` | exclusive `QToolButton`s |
| `QtImage` | `QLabel` over a spacer of the natural size, scaled on resize; a FIT height follows the width |
| `QtScrollView` | `QScrollArea`, widget resizable; transparent: its viewport and the widget it holds fill no background (`setAutoFillBackground(false)`; `setWidget()` turns it on for the widget, ext-qt 43f9f95), so its container's background shows through; a background set on it is its sheet's, painted behind them |
| `QtTabView` | `QTabWidget` |
| `QtSplitView` | `QSplitter`; `splitterMoved` is the user's alone; a resize puts the fraction back |
| `QtGrid` | `QGridLayout`; an empty last row and column take spare room while nothing fills; padding as the layout's margins, each side its own, live |
| `QtOverlay` | `QWidget` with a `QGridLayout`: every child in cell (0, 0) with its alignment (FILL is no flag), padding as the layout's margins, live. The first child is at the back: the widgets are `raise()`d in the children's order after every attach and reorder. A child that fills both ways has `IGNORED` size policy both ways (also kept by `QtNative::applySizePolicy()`), so Qt neither reads its hint nor its minimum hint: it takes the cell and never sizes the overlay; the natural size is the largest of the others. A child with a margin is in the cell in its margin holder (see Settings) |
| `QtTable` | `QTableWidget`, whole rows, one at a time |
| `QtTextArea` | `QPlainTextEdit`; styles as extra selections, which follow the user's edits |
| `QtListView` | `QListView` painted by a `QPaintDelegate` (`QtItemView`) |
| `QtCollectionView` | the same, icon mode, wrapping; a click activates |
| `QtWebView` | `QWebEngineView` (Chromium; ext-qt 1f55bfe). `load()`/`loadHtml()` are `load(QUrl)`/`setHtml(html, QUrl(baseUrl ?? ''))`, `reload()`/`stop()` the view's. `url()`, `title()`, `isLoading()` read the view's `QWebEnginePage` (empty url or title is null). The page's `loadingChanged(QWebEngineLoadingInfo)` ends a load: `LoadSucceededStatus` calls `loaded(url)`, `LoadFailedStatus` calls `failed(url, errorString)` with Qt's text (`net::ERR_NAME_NOT_RESOLVED`); started and stopped post nothing. The callback holds the primitive weakly and is disconnected on release. `supported()` is true |
| `QtVideo` | the widget of a player from the video manager's driver (`qt.video.driver`): `qt` (the default) a host `QWidget` with a `QVideoWidget` fed by a `QMediaPlayer` and a bar of Qt's theme icons while it has controls; `webview` a `QWebEngineView` showing the media as its document. `QtVideo` keeps no player code; `supported()` is the driver's (`qt`: `QMediaPlayer::isAvailable()`; `webview`: true). See [Video](/design/video.md) for both players' rules. Offscreen Qt's media backend never finishes loading, so `VideoTest` skips there and runs on Cocoa, every case on both drivers |
| `QtTree` | `QTreeWidget`; a header with no titles gets no height by style sheet (ext-qt binds no `setHeaderHidden`) |

# Settings

Topside's optional hooks, done with Qt's own API where Qt has one; elsewhere the hook stays empty and the setting is not shown (the getter still answers what was set).[^native][^margin][^held]

| Setting | Qt |
|---|---|
| Padding (column, row, grid, tab page) | the layout's `setContentsMargins(left, top, right, bottom)`, at build and on every change |
| Margin: label, link, check box, text input, progress bar | style sheet `margin` (`QtSheetMargin`): Qt's sheet box paints the background inside it and adds it to the size hint, so the layout leaves the space; a label or link has indent 0 while it has a margin. These five are `QtKeepsOwnMargin`: no parent adds a margin round them |
| Margin: every other kind, in a column, row, overlay or grid | the parent keeps it (`QtHeldMargin`): the child in a nested `QHBoxLayout` whose contents margins are the margin, the child in it with its alignment. In a column, the row an aligned or capped child already sits in takes the margin; any other child with a margin gets a holder of its own (shape `margin`), in a column or a row. An overlay and a grid add the holder with `addLayout()` filling the cell, the child aligned inside it. A margin changed live is written to the holder, or the child is put back the new way (into a holder, out of one). A hidden child's holder has no contents margins (Qt keeps them after its only widget is hidden), so its margin takes no room |
| Margin: every other kind, in a fixed | the frame moves in by the left and top margin; the fixed's minimum size reaches past the right and bottom margin |
| Margin: the page of a tab view, a pane of a split view, a scroll view's content | each takes its child as one widget with no layout round it, so the child is always in a holder widget of its own (`QtHeldMargin::marginWidget()`): a plain `QWidget` whose `QHBoxLayout` has the margin as contents margins, none when it has none, so a change of margin is the holder's alone and no widget is swapped in the container. The tab view's page, the splitter's pane and the area's widget are the holder; a hidden child's pane is hidden with it, and a hidden child's holder has no margins |
| Corners | the four sheet properties `border-top-left-radius` … `border-bottom-left-radius`, a zero corner left out; never the single `border-radius` (`applyCornerRadius()` writes the same four). They round the background and a border |
| Watch size | `QtNative::applyWatchSize()`: a `QEventFilter` on the widget for `RESIZE` that calls `sizeChanged()` (topside posts `ViewResized` once per pump, only for a size it has not posted, never with a 0 side). It sits beside the click filter, which stays; removed when watching stops and on release. `tests/Integration/ViewResizedTest.php` |
| Clickable group | every group (column, row, grid, fixed, overlay, scroll view, tab view, split view): a `QEventFilter` on its widget that only watches (returns false). A left press reaching the widget, then a left release inside its rect, calls `groupClicked(x, y)` with the release's position, which Qt gives in the group's coordinates. Qt hands the group a press only when nothing under the pointer accepted it: a button or a line edit accepts its own (no group click), a plain label or a picture ignores it, so it reaches the group. Off, and on release, the filter is removed |
| Move transitions | `MOVE_RIGHT`/`LEFT`/`TOP`/`BOTTOM`: one `QPropertyAnimation` of `pos` from one own width or height toward the edge to where the layout put it, along topside's `TKTransition::curve()`: a `QEasingCurve` of type `BEZIER_SPLINE` with one `addCubicBezierSegment()` (ext-qt c65bd19) from (0, 0) through c1 = (x1, y1), c2 = (x2, y2) to (1, 1); `MOVE_IN_CURVE` (0.22, 1, 0.36, 1, easeOutQuint) appearing; disappearing back out along `MOVE_OUT_CURVE` (0.64, 0, 0.78, 0, easeInQuint), hidden on its `finished()`, then put back at rest. No opacity effect is made. FADE and SLIDE_* run as before (an opacity effect, linear) |
| Label runs | Qt rich text (`RICH_TEXT`): each run's text escaped (`htmlspecialchars`), in `<b>`, `<i>` and `<span style="color: …">` (`#rrggbb`, `rgba()` when translucent) as it asks; a plain run takes the label's sheet font and colour. The whole is in `<span style="white-space: pre-wrap">`, so spaces and line breaks show as plain text shows them (a space at a run's edge stays). Wrap is kept. `setText()` returns to `PLAIN_TEXT`, so a later `<` shows as itself |
| Maximum size | `setMaximumWidth()` / `setMaximumHeight()`; 0 is none (`QWIDGETSIZE_MAX`, 16777215). A layout gives an aligned widget no more than its size hint (`QWidgetItem::setGeometry()`), and a container's hint is its children's, so a column, row or overlay that fills with a maximum makes its own layout prefer that maximum: a column's (or row's) trailing stretch takes the maximum as its preferred cross size, an overlay's cell holds a spacer preferring it (both shrink to nothing, `PREFERRED`). Centred, it is as wide as its room up to the maximum. Along a column's or row's own axis the hint stays its children's; a grid and a leaf keep their own hint, so centred they are their natural size, capped; with FILL alignment anything takes its room up to the maximum, at the start |
| Button icon position | not shown: a `QPushButton` draws its icon before its label and Qt has no option to put it after; the icon stays leading |
| Homogeneous column or row | every child stretch factor 1 and its size policy along the axis `IGNORED` (kept by `QtNative::applySizePolicy()`, which reads the parent), the trailing stretch 0: Qt's layout reads no hint that way and shares the room by the equal factors alone. Without it Qt's stretch also shares equally, but only while every child's hint fits its share; a child wider than its share keeps its width. A child added later joins; a hidden child takes no share; a child's maximum caps it inside its share. Off, each child gets its stretch from its fill and its own policy back. A homogeneous column or row reads no child length, so its own natural length along the axis is its padding and spacing: give it room (fill) |
| Clip | not shown: Qt Widgets clip a child to its rectangle only, and a rounded mask would be drawn, not native. The image rounds its own picture (below) |
| Image corners | the label shows the picture as scaled for the label (FIT fitted, FILL covering and cropped to the label, centred, STRETCH stretched, CENTER at its own size, cropped when larger), drawn with `QPainter` into a transparent copy of it through a `QPainterPath` of lines and one `arcTo()` per corner, antialiased; again on every resize and change. Zero corners: the plain path as before |
| Cursor | `setCursor(QCursor(shape))`: arrow, pointing hand, I-beam, cross, size-all, forbidden, open hand, closed hand, size hor/ver, size F/B diagonal; null `unsetCursor()` |
| Tooltip | `setToolTip()`; null is `''` |
| Border | style sheet `border: Wpx solid <colour>`; no colour is `palette(mid)`, read by the sheet from the palette. A plain `QWidget` keeps `STYLED_BACKGROUND` on while a border or a background is set. A border set takes the place of the widget's own: a scroll view's `none`, a button's background-coloured line |
| Button style | HELP: Qt has no help button, so DEFAULT's look, its label shown. BORDERLESS: `setFlat(true)` and sheet `border: none` (no padding, even with a background). LINK: the same and sheet `color: palette(link)`; topside sends the pointing hand. DEFAULT: `setFlat(false)`, the sheet as before |
| Button padding | style sheet `padding: <top>px <right>px <bottom>px <left>px`, per side; `Insets::none()` removes it and `restyleBox()` gives back what the adapter declares otherwise (`4px 12px` on a framed DEFAULT button with a background or border, else none). A set padding on a DEFAULT button with no background swaps the macOS bezel for a sheet-drawn frame (see Checked) |
| Button font, colour, alignment | sheet `font-*`, `color`, `text-align` (`QtText`); a set colour wins over the link colour |
| Button icon | `setIcon(QIcon(QPixmap))` from the file, else `QIcon::fromTheme(symbol)`, else an empty icon; Qt puts it before the label |
| Button role | DEFAULT: `setDefault(true)`, `setAutoDefault(true)`. Qt clicks a focused default button on Return; outside a `QDialog` an unfocused one is not clicked (Qt's own behaviour, no shortcut added). CANCEL: Qt has no cancel button outside a dialog, so not shown |
| Search field | `setClearButtonEnabled(true)` and `addAction(QIcon::fromTheme(ThemeIcon::SYSTEM_SEARCH), LEADING_POSITION)` when the theme has the glyph (macOS 15 does); fixed at build |
| Borderless field | `setFrame(false)`, `MAC_SHOW_FOCUS_RECT` off, and sheet `background-color: transparent` (a frameless `QLineEdit` still paints its base colour; seen); false restores all three |
| Read-only, max length | `setReadOnly()`, `setMaxLength()`; no limit is Qt's 32767. Qt cuts a longer text, from `setMaxLength()` or `setText()`, and signals the cut as `textChanged`: the max length is set inside `write()` (no typing), and both hooks hand topside the field's `text()` through `cutTo()`, so `value()` is what is on screen and nothing is posted |
| Link colour | `style="color: …"` on the anchor the link builds: a `QLabel` draws anchors in the palette's link colour, not the sheet's; null leaves the palette's |

Margin, measured in a real window (macOS 15, Qt 6.11.2, 2026-11-24): Qt layouts keep no space round a child, so the only native margin is the style sheet's box. With `margin: 5px 7px 11px 13px` on each kind between two labels:

* Label, link, progress bar: the size hint grows by exactly 20 × 16 and the next item moves 16 down. Under a sheet box a label has a frame, and Qt's default indent (-1) then indents its text by half an `x` and widens its hint by a whole one (7 px); a label or link with a margin has `setIndent(0)`, and gets -1 back when the margin goes (ext-qt 53b591e).
* Check box and text input: exact (20 × 16) against the same widget under a sheet box with no margin; the sheet box itself drops Qt's native focus allowance (check box 63 × 20 → 59 × 18, text input 125 × 21 → 125 × 20), so against no sheet they grow 16 × 14 and 20 × 15. Look unchanged in a screenshot.
* In all five the background is painted inside the margin: red background, no red at the four margin sides, red inside.
* Not shown by the sheet, the size hint unchanged (0 × 0): column, row, grid, fixed, split view, tab view (plain `QWidget`s or containers whose hint comes from their layout), separator, spinner, segmented control, image, text area, list, collection, table, tree. Their margin is the parent's to keep (`QtHeldMargin`, 2026-11-26).
* Not shown, the sheet box changes the control: button and toggle button (any sheet `margin`, even `0px`, swaps the macOS bezel for a sheet-drawn frame, 70 × 32 → 42 × 18), dropdown, combo box and date picker (frame and text lost or clipped), slider (handle clipped), switch (fixed width: the margin squeezes the knob), scroll view (grows 26 × 26, not 20 × 16).

# Notes

* Resizing the window holds the pump until release on macOS (measured by hand 2026-11-22: 3.6 s with no pump return), so timers and mail wait; a repeating timer then fires once and skips the beats it missed.
* Styling: one style sheet per widget, scoped to its object name, so it does not reach the widgets inside it.
* Opacity and transitions: a `QGraphicsOpacityEffect` parented to the widget; transitions are `QPropertyAnimation`s Qt runs (fade, and a `pos` slide).
* Release: `setParent(null)` + `deleteLater()`, flushed by the session's pump.
* `nativeFocus()` refuses a `NO_FOCUS` widget (`setFocus()` ignores the policy). `hasFocus()`: the window's `focusWidget()` (ext-qt 12940eb).

* Web engine and the window: a `QWebEngineView` holds a `QQuickWidget`, and the first one in a shown window makes Qt recreate the window's native surface (raster to Metal; Qt log `Recreating QWidgetWindow ... to support QSurface::MetalSurface`). Done inside a mouse event (a click that opens a page) the new window is never painted: the whole window stays one grey, widget geometry all correct. `Qt` therefore sets `QT_WIDGETS_RHI=1` (unless already set) and `AA_ShareOpenGLContexts` (Qt's requirement for QtWebEngineWidgets) before the `QApplication`, so every window flushes through QRhi from the start and nothing is recreated.
